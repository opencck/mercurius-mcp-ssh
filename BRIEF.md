# mercurius-mcp-ssh

## Назначение и границы

MCP-сервер по stdio для одного SSH-сервера: команда, файл через `cat`, TCP-проба. Это SSH-модуль Меркурия
(сабмодуль `mcp/ssh`): каждый сервер — запись `.mcp.json` со своим процессом. Сервер ничего не решает о том, что
команде можно: классификатор, правила «никогда без владельца», карточки и журнал — в ядре Меркурия вокруг его
инструментов. Не входит (пока): SQL через туннель, маршруты (прокси, VLESS, промежуточный хост), sudo через stdin.

## Устройство

- `Options` — хост, порт, логин, файл ключа, закреплённый ключ хоста из аргументов; пароль и пароль ключа — из
  окружения (`SSH_PASSWORD`, `SSH_KEY_PASSPHRASE`).
- `SshRemote` — одно соединение `amphp/ssh`, открывается первым вызовом и держится; умершее открывается заново один
  раз. Команда — `timeout --kill-after=5 <сек> sh -c …`; вывод — по 64 КБ каждого потока.
- `Server` — JSON-RPC по строкам: `initialize`, `tools/list`, `tools/call`, `ping`.

## Решения

- **Ключ хоста только закреплённый.** Без `--host-key` или при другом ключе соединение обрывается до входа, вызов
  отвечает `UNKNOWN_HOST_KEY <отпечаток> new|changed`: закрепляет ключ владелец через ядро.
- **Секреты — в окружении процесса**, не в аргументах: аргументы видны в списке процессов.
- **Файлы через `cat`**, как в ядре Меркурия: без SFTP.

## Проверки

`composer check` — PHPUnit, PHPStan (max), Psalm (уровень 1); то же в GitHub Actions на PHP 8.2.
